# NadirRemote — собственная версия на базе RustDesk

Статус: исходники изменены; Windows EXE ещё не собран и не проверен.
Это новый проект на базе RustDesk, а не развитие предыдущего Python-прототипа.
Рабочее название — NadirRemote. Целевая платформа — Windows 10/11 x64.

## Что сделано

- Собственное имя приложения NadirRemote, свойства EXE, значок и логотип.
- Имя применяется до инициализации конфигурации: служба, каталог установки и
  настройки используют имя NadirRemote. Техническое имя DLL librustdesk.dll
  сохранено для совместимости сборки; это не видимый бренд приложения.
- Сохранён штатный установщик RustDesk. Он создаёт службу Windows с автозапуском.
- Добавлен Install-NadirRemote.ps1 для установки и проверки службы.
- Добавлены атрибуция и кнопка «Исходный код» в «О программе».
- Подготовлена ручная сборка Windows x64 через GitHub Actions с выходом в EXE и ZIP.
- В каждый дистрибутив включается архив соответствующих исходников source.zip.

Изменение имени включает штатное поведение custom client, в том числе прекращает
обычную проверку обновлений официального RustDesk. Обновления своей версии нужно
собирать и распространять отдельно; автоматического канала обновлений NadirRemote нет.

## Что остаётся от RustDesk

Интерфейс и функции исходного проекта: ID компьютера, пароль, удалённый экран,
мышь, клавиатура, передача файлов, служба Windows и соединение через интернет.
Это форк с собственным оформлением, а не новая разработка протокола с нуля.
Возможности этой конкретной сборки ещё требуют проверки на Windows.

## Как получить EXE

В текущем архиве лежат исходники, не установщик. Сборка требует Windows toolchain;
готовый сценарий запускается на Windows runner GitHub Actions.

1. Создайте пустой репозиторий GitHub для своего проекта. Не включайте автосоздание
   README, чтобы первый push не требовал слияния. Исходники можно держать приватно
   во время разработки; при распространении соблюдайте требования AGPL.
2. Установите Git for Windows. Распакуйте исходный архив в отдельную папку.
3. Откройте терминал в папке NadirRemote с Cargo.toml и выполните, заменив
   ВАШ_ЛОГИН на своё имя GitHub (репозиторий должен уже существовать):

```powershell
git init
git add --force --pathspec-from-file=nadir/source-files.txt
git commit -m "Prepare NadirRemote Windows fork"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/NadirRemote.git
git push -u origin main
```

Команда git add использует проверенный список исходников: обычный git add .
пропустит изображения и часть файлов, которые upstream исключил через .gitignore.

В архиве hbb_common уже включён как обычные исходники, поэтому отдельно скачивать
его не нужно. Остальные зависимости скачиваются при сборке из источников,
указанных upstream. Для доступа к GitHub используйте обычную авторизацию Git;
не отправляйте пароли или токены в чат.

4. На GitHub откройте Actions → Build NadirRemote for Windows → Run workflow.
5. После успешного завершения скачайте artifact `NadirRemote-Windows-x64`.
   В нём должны быть:
   - NadirRemote-Setup.exe — самораспаковывающийся EXE со штатным интерфейсом установки;
   - NadirRemote-Windows-x64.zip — полный распакованный дистрибутив.

Workflow создан по Windows-сборке того же upstream-коммита. Он ещё не запускался;
при ошибке нужен журнал неудачного шага. Стоимость/квота Actions зависят от вашего
аккаунта. Сборка запускается только вручную, ничего не публикует в Releases.
Исходные workflows сохранены в nadir/upstream-workflows как справочный материал,
чтобы при импорте не запускались задания для других платформ.

## Установка и автозапуск после успешной сборки

1. Запустите NadirRemote-Setup.exe на своём ПК.
2. Выберите установку и подтвердите стандартный запрос администратора Windows.
3. В настройках безопасности задайте свой постоянный пароль для доступа без
   подтверждения. Пароль не встроен в программу и не задаётся разработчиком.
4. Убедитесь, что служба NadirRemote запущена и имеет тип запуска «Автоматически».
5. Установите ту же программу на второй компьютер и подключитесь по ID и паролю.

Альтернатива: распакуйте весь NadirRemote-Windows-x64.zip и запустите
Install-NadirRemote.ps1 в PowerShell от администратора, если политика вашей
системы разрешает запуск скриптов. Скрипт показывает подтверждение INSTALL,
использует штатную установку, проверяет службу и включает её автозапуск.
Если скрипты запрещены, используйте обычную установку через интерфейс EXE.

Автозапуск означает работу службы после включения Windows. Он не включает
выключенный компьютер и не удерживает ПК от сна. Первый запуск требует установки
и задания пароля; затем подтверждать каждый сеанс на удалённом ПК не нужно.
Остановить доступ можно в настройках программы или остановкой службы NadirRemote.
Удаление — через «Установленные приложения» Windows.

## Интернет и обычный хостинг

В исходниках сохранена штатная конфигурация публичных серверов RustDesk.
Ваш хостинг сайта не участвует в соединении. Это зависимость от инфраструктуры
RustDesk: работа изменённой сборки на ней не проверена и не гарантирована.
Для полностью собственного сервиса потребуется отдельный ID/relay-сервер.
Адрес своего сервера можно будет задать штатно в сетевых настройках на обоих ПК.
Ни отдельный VPN-адаптер, ни проброс портов на домашнем роутере этим проектом
автоматически не устанавливаются.

## Проверки перед использованием

В этой среде выполнены: проверка изменений исходников, синтаксиса Python-сборщика,
структуры YAML workflows, существования локальных workflow-зависимостей, упаковки
исходников и читаемости иконок. Windows toolchain отсутствует, поэтому компиляция,
запуск программы, UAC, автозапуск и подключение через интернет ещё НЕ проверены.

После сборки проверьте на двух своих ПК:

- интерфейс и значок NadirRemote, отдельный каталог и служба;
- вход по правильному паролю и отказ по неверному;
- экран, мышь, клавиатура и передачу тестового файла;
- перезагрузку управляемого ПК и повторное подключение до входа в Windows;
- наличие source.zip рядом с установленным EXE и кнопку исходников;
- остановку службы и штатное удаление;
- подключение между разными сетями, например домашним интернетом и мобильной точкой.

Сборка не подписана вашим сертификатом издателя. Windows может показать
предупреждение об неизвестном издателе. Для публичного выпуска потребуется
отдельно организовать подпись и обновления.

## Область изменённого поведения

- src/common.rs: имя для Windows до загрузки конфигурации; необходима отдельная
  идентичность приложения, службы, настроек и каталога. Непосредственно сетевой
  протокол и механизм проверки паролей не изменены.
- flutter/windows/runner/Runner.rc и ресурсы значков: бренд в свойствах EXE.
- flutter/assets: собственные значок и логотипы для светлой/тёмной темы.
- flutter/lib/desktop/pages/desktop_setting_page.dart: атрибуция и ссылка на
  локальный архив исходников в «О программе» на Windows.
- .github/workflows: только ручная сборка Windows, упаковка исходников вместе
  с программой; исходные автоматические workflows вынесены в справочную папку.
- nadir/: установка, инструкции, происхождение и сборщик исходного архива.

Новые изменения не добавляют скрытого запуска, общего пароля или отключения защиты.
Автозапуск реализуется штатной службой, которую пользователь устанавливает явно.
